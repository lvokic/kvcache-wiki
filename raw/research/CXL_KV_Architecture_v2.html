01 / DEPLOYMENT

主路径明确经过 host；CXL 是存储层

CPU retrieval 完成候选生成和原 K 精排，交出最终选集及 selected K lease；planner 据此查物理位置。GPU 保留权重、热 KV 与有界工作区；CPU/DRAM 提供索引、gather 和 partial attention。

02 / VECTOR RETRIEVAL

IVF 为起点；RoarGraph + CXL-Vector 为主研究候选

IVF 与 RoarGraph 决定路由拓扑，CXL-Vector 提供压缩导航与分层执行机制。每个 layer/KV group 先配置一种索引；下图中的 A、B、C 是替代实现。原精度 RoarGraph 隔离拓扑收益，IVF-SQ8 与组合路线共用重排后端，避免用不同执行优化制造差距。

相较 v2 的关键修正：最终选集确定之前，候选精排已经可能读取 CXL。索引阶段与 attention 阶段共享带宽 credits；精排取得的 K 以 lease 交给后端。最后只补缺失 V，避免重复读 K。

K lease 绑定 request/layer/group/epoch/token、原精度、ready event 和消费者计数；logits 还绑定 step/head/score semantics。未选 K 尽早释放，选中 K 在 CPU 读取或 H2D 完成后才可回收。buffer 有界；失效后重读必须计量。GQA 的 candidate union 只去重读取，每个 head 仍只在自己的候选中精排。

构建与追加

Roar 用当前可见 prefill/已发生 decode 的 Q，不能偷用未来 Q。FlashAttention 不免费输出建图邻接。MVP 为 immutable base + 精确 delta；封存段完成 backing/codes/index 后发布。多段 fan-out、compaction、旧新版本双份容量全部计入。

内核与精度

分离 neighbor/visited 与 SIMD distance，分批预取。首先 SQ8，随后 TQ5；原 K 精排恢复候选分数，无法救回漏搜节点。初版 exact visited；128K 节点 bitset=16 KiB/活跃搜索。Bloom visited 仅作为有召回代价的消融。

CXL 流量不是最终 top-k 的 KV 大小

有效冷读 payload = dK × bytesK × |候选 union 的 K misses|
                  + dV × bytesV × |最终 union 的 V misses|
实际流量另加：transaction / page 放大、导航溢出、K 重读与维护。
无命中、无跨 head 重叠、K/V 等大：放大 = (R/k + 1)/2。
例：R = 4k → 2.5 倍最终 K+V payload。此例不是测量结果。

一个会改变选型的容量边界

32层 × 8 KV groups × 128K tokens × d128/BF16，原 K/V 各8 GiB。每节点32条4-byte边，邻接表4 GiB；SQ8 codes 4 GiB。原 K 常驻的 graph+K 至少12 GiB；分层 graph+SQ8 至少8 GiB，尚不含元数据、Q 样本、建图空间与 staging。组合路线不能自动解决所有 DRAM 压力；IVF 不承担逐节点32条边的容量。

检索侧最值得验证的假设

Roar 的 OOD 拓扑收益，能否在压缩导航后保留，并以更小的原 K 重排流量达到相同 attention 质量？固定 topology，分别测原精度/SQ8/TQ5；再调 W 与 R。记录 recall、保留 softmax mass、生成任务质量、候选 K bytes、最终 V bytes、建图与 TTFT。图更少的 visited 不自动等于更少的 CXL bytes。

原精度 IP 排名不等于归一化 K 后的 cosine。不能把 approximate codes 分数交给 softmax。新前缀短输出优先验证 IVF；复用长前缀/长 decode 才更可能摊薄 Roar 构建成本。无法稀疏化的层直接走 full 路径。

依据：用户 CXL-Vector 稿件§3–5（SQ8/TQ5、HNSW/NSG，Roar 适配尚待实现）；RoarGraph；官方代码；Faiss IVF；RetrievalAttention。将 Roar 用于 attention 已有先例；组合的质量、性能与新颖性尚未得到实验确认。

粒度独立；buffer 与 snapshot 各有状态机

对象作用约束
Backing page每 request/layer/KV group 的 K/V arrays初始16 tokens；d128/BF16：K+V=8 KiB，不是 OS page
Extent同 tier/epoch 的连续地址范围保留原始 position 映射
Packet紧凑 payload、offsets、mask、valid length有界 ring，attention 直接消费
TileGPU CTA / CPU SIMD 运算单位硬件与 shape 决定，不等于 page

            head_indptr, token_ids, selected_K_lease }
Work      { route, span_or_offsets, head_mask, original_positions,
            packet_slot, completion_slot }
Partial   { req, step, layer, head, partition_id, epoch,
            state_format, m, z, u }

Packet ring

FREE → FILLING → H2D → COMPUTING → FREE

最后一个消费者完成后才能复用 slot；无 credits 就回压。异步 cache install 也是消费者。

Append publication

GPU_VISIBLE → COPY_PENDING → BACKING_READY → INDEX_READY → PUBLISHED

snapshot=已索引前缀+精确可访问 delta，二者不重不漏。backing 与索引就绪才推进水位；旧 epoch 读者结束才回收。

稳定归并：m=max(mₐ,mᵦ)；z=emₐ−mzₐ+emᵦ−mzᵦ；u 同样加权；o=u/z。空分区用 validity；backend 的 LSE 对数底、scale、dtype 必须验证。
06 / DECISION MECHANISM

比较 layer 完工时间，不只比较 bytes

输入

真实 union/mask、span 数与密度、HBM hit、source tier、CPU/GPU queue、buffer credits。

有限候选

resident 原地；whole-group CPU；whole-group pack；bulk+residual；可用时 mapped。

cost(action) = { CXL bytes, DRAM bytes, H2D/D2H bytes,
                 CPU time, GPU time, workspace, launches }
choose = smallest predicted layer finish time
subject to = same mask + same epoch + capacity credits
split only if = gain > plan + synchronization + merge cost

从查表/分段 profile 和粗 bundle 启动；合并小任务，只允许少量分区。全 CPU、全 GPU、whole-group 都是合法赢家。

CPU partial 省的是 KV 的 H2D，不自动省 CXL 读取。两设备共读 CXL 时不能各按独占满速估算。

08 / CLAIMS & VALIDATION

贡献边界与否定实验

复用待验证必须比较
ANN、paging、state merge、bulk copy、GQA reuseselection 后 footprint；group 内有限分流；有界执行契约同选集下最佳固定路径、优化 whole-group、mixed；包含 plan/join

Fluxion 已有 whole-group 调度，SPIN 已优化分层 copy，FlashInfer 已有稀疏 gather，CompactAttention 已有 mask→GQA block table。仅组合接口、免 scatter 或加入 CXL 不足以构成贡献。

本轮以 NumPy 检查相同 mask 的跨分区稳定归并与上方实例；这不验证 CUDA/CPU kernel、并发实现、模型质量或性能。
